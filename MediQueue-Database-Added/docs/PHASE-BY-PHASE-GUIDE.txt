MediQueue Web: Phase-by-Phase Build Guide
Oct 22, 2026 · @Potzzzzz
Before you start
By the end of this guide, MediQueue runs as a website: the same clinic app, with your Java code as the backend and a browser page as the frontend. You build it in 11 phases, and each phase ends with a checkpoint you test before moving on.

How MediQueue Web fits together · 6 parts
MediQueueData.java, the highlighted box, comes from the desktop project unchanged, and MediQueue.java beside it stays the desktop app. Phases 2 to 4 build the server side, Phases 5 to 9 the browser side, and Phase 10 packs everything into two .jar files.
What you need
•JDK 17 or newer. In a terminal, java -version and javac -version should both print a version.
•VS Code (or any editor) with a terminal open in your project folder: Terminal > New Terminal.
•A web browser, such as Chrome or Edge.
•The original project from GitHub: the MediQueue-Project folder with src/MediQueue.java and src/MediQueueData.java.
•curl for the server tests in Phase 4. It comes with Windows 10/11 (type it as curl.exe) and with macOS.

How to follow the phases
1.Do the phases in order. Each one builds on the files from the phase before.
2.Put every code block in the file named right above it, exactly as shown. Copying is safer than retyping.
3.When a step says paste above the last }, put the code inside the class, just before its final closing brace.
4.Run the checkpoint at the end of each phase. If it does not match, fix that first; the next phase depends on it.
5.Commands work in VS Code's terminal on Windows, macOS and Linux. Where Windows needs something different, the step says so.
If you get stuck, compare your file with the same file in MediQueue-Web.zip.

Phase 2: Json.java
The browser and the server talk in JSON, a text format for data. Java has no built-in JSON writer and this project uses no libraries, so Phase 2 adds a small one of its own.
Two answers the server will send later, the second one shortened:
{"error":"That slot is already booked. Pick another time."}
{"ok":true,"message":"Appointment confirmed.","tone":"green","state":{...}}
Step 2.1: Create src/Json.java
package mediqueue;

import java.util.Arrays;
import java.util.LinkedHashMap;
import java.util.Map;

/**
 * A very small JSON writer, so the web server needs no extra libraries.
 * It turns Maps, Lists, Strings, numbers and booleans into the JSON text that the browser reads.
 *
 *   Json.write(Json.obj("name", "Ana", "age", 26))   gives   {"name":"Ana","age":26}
 */
final class Json {
    private Json() { }

    /** Builds an ordered map from key/value pairs:  obj("name", "Ana", "age", 26). */
    static Map<String, Object> obj(Object... keysAndValues) {
        Map<String, Object> m = new LinkedHashMap<>();
        for (int i = 0; i + 1 < keysAndValues.length; i += 2) m.put(String.valueOf(keysAndValues[i]), keysAndValues[i + 1]);
        return m;
    }

    /** Converts a value (and everything inside it) to JSON text. */
    static String write(Object value) {
        StringBuilder sb = new StringBuilder();
        append(sb, value);
        return sb.toString();
    }

    private static void append(StringBuilder sb, Object v) {
        if (v == null) {
            sb.append("null");
        } else if (v instanceof String) {
            quote(sb, (String) v);
        } else if (v instanceof Number || v instanceof Boolean) {
            sb.append(v);
        } else if (v instanceof Map) {
            sb.append('{');
            boolean first = true;
            for (Map.Entry<?, ?> e : ((Map<?, ?>) v).entrySet()) {
                if (!first) sb.append(',');
                first = false;
                quote(sb, String.valueOf(e.getKey()));
                sb.append(':');
                append(sb, e.getValue());
            }
            sb.append('}');
        } else if (v instanceof Iterable) {
            sb.append('[');
            boolean first = true;
            for (Object item : (Iterable<?>) v) {
                if (!first) sb.append(',');
                first = false;
                append(sb, item);
            }
            sb.append(']');
        } else if (v instanceof Object[]) {
            append(sb, Arrays.asList((Object[]) v));
        } else {
            quote(sb, v.toString());
        }
    }

    /** Writes a string in quotes, escaping the characters JSON does not allow as-is. */
    private static void quote(StringBuilder sb, String s) {
        sb.append('"');
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            switch (c) {
                case '"': sb.append("\\\""); break;
                case '\\': sb.append("\\\\"); break;
                case '\n': sb.append("\\n"); break;
                case '\r': sb.append("\\r"); break;
                case '\t': sb.append("\\t"); break;
                default:
                    // Control characters, plus < > & as an extra precaution, are written as numbered escape codes.
                    if (c < 0x20 || c == '<' || c == '>' || c == '&' || c == 0x2028 || c == 0x2029) sb.append(String.format("\\u%04x", (int) c));
                    else sb.append(c);
            }
        }
        sb.append('"');
    }
}
How it works:
•obj("name", "Ana", "age", 26) builds a map that keeps the keys in the order you gave them, so the JSON always reads the same way.
•write(value) walks through maps, lists, strings, numbers and booleans, and builds the JSON text.
•quote(...) wraps a string in quotes and escapes the characters JSON does not allow as-is, such as " and line breaks.
•The class is not public: only classes in the mediqueue package use it.

Phase 3: MediQueueService.java
Phase 3 moves the clinic rules out of the desktop screens. In MediQueue.java, each rule sits in a button handler that reads text fields and shows an error label. A web server has no text fields, so each rule becomes a plain method: values in, a result out, or a UserError with the desktop's exact message.

Step 3.1: Create src/MediQueueService.java
package mediqueue;

import java.time.DayOfWeek;
import java.time.LocalDate;
import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.time.format.TextStyle;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.List;
import java.util.Locale;
import java.util.Map;

import static mediqueue.Json.obj;
import static mediqueue.MediQueueData.*;

/**
 * MediQueue's clinic rules, taken out of the desktop screens so the web server can use them.
 *
 * In the desktop app (MediQueue.java) these rules sit inside button handlers such as doLogin(), doRegister()
 * and book(). Here every rule is a plain method: it returns a result, or throws a UserError carrying the same
 * message the desktop app shows. The data itself still lives in MediQueueData (the lists and the two text
 * files), which is used without any changes.
 *
 * Only one request may touch the data at a time, so callers hold the lock on MediQueueData.class
 * (MediQueueWeb does this for every request).
 */
final class MediQueueService {
    private MediQueueService() { }

    /** A problem the user can fix, such as a wrong password or a time slot that is taken. Its message is shown on screen. */
    static final class UserError extends RuntimeException {
        private static final long serialVersionUID = 1L;
        final int status;   // the HTTP status code sent to the browser (400 = bad input, 403 = not allowed, ...)
        UserError(String message) { this(400, message); }
        UserError(int status, String message) { super(message); this.status = status; }
    }

    static final String FEE = "₱100.00";
    static final int DAYS_AHEAD = 60;   // the desktop date lists offer the next 60 days
    static final List<String> SLOT_CHOICES = Arrays.asList("9:00 AM - 12:00 PM", "9:00 AM - 3:00 PM", "10:00 AM - 2:00 PM", "1:00 PM - 5:00 PM");
    static final List<String> GENDERS = Arrays.asList("Female", "Male", "Other");
    static final DateTimeFormatter CLOCK = DateTimeFormatter.ofPattern("h:mm a", Locale.ENGLISH);
    private static final String UNKNOWN_USER_SALT = newSalt();
}
import static mediqueue.MediQueueData.*; lets this class use APPTS, QUEUE, PATS, SCHEDS, ACCOUNTS and the helper methods of MediQueueData directly, the same way MediQueue.java does. UserError carries the message for the screen plus an HTTP status code: 400 for bad input, 403 for not allowed, 404 for not found.

    // =====================================================================
    //  ACCOUNTS  (desktop: doLogin, doRegister, doReset, startSession)
    // =====================================================================

    static Account login(String username, String password, String role) {
        Account a = ACCOUNTS.get(username.trim().toLowerCase());
        // Hash the password even for an unknown username, so a wrong username takes as long as a wrong password.
        String attempt = password.isEmpty() ? "" : hash(password, a != null ? a.salt : UNKNOWN_USER_SALT);
        boolean ok = a != null && a.role.equals(role) && !password.isEmpty() && sameHash(a.hash, attempt);
        if (!ok) throw new UserError("Invalid username or password.");
        startSession(a);
        return a;
    }

    static Account register(String nameIn, String contactIn, String userIn, String pw, String pw2) {
        String name = clean(nameIn, 60), contact = clean(contactIn, 20), user = userIn.trim();
        String problem = null;
        if (name.length() < 2) problem = "Please enter your full name.";
        else if (!contact.matches("[0-9+\\-\\s]{7,15}")) problem = "Enter a valid contact number (7-15 digits).";
        else if (!user.matches("[A-Za-z0-9_.]{3,20}")) problem = "Username: 3-20 letters, numbers, . or _";
        else if (pw.length() < 6) problem = "Password must be at least 6 characters.";
        else if (!pw.equals(pw2)) problem = "Passwords do not match.";
        else if (ACCOUNTS.containsKey(user.toLowerCase())) problem = "That username is already taken.";
        else for (Account x : ACCOUNTS.values()) if (x.name.equalsIgnoreCase(name)) problem = "A patient with that name is already registered.";
        // Web only: the clinic may already have a record with this exact name (added by staff). Anyone can open a
        // website, so the contact number on that record must match before the new account is linked to it.
        Pat record = recordOf(name);
        if (problem == null && record != null && !digits(record.contact).equals(digits(contact)))
            problem = "The clinic already has a record with that name. Use the contact number on file.";
        if (problem != null) throw new UserError(problem);
        Account a = makeAccount(user, "patient", name, contact, pw);
        ACCOUNTS.put(user.toLowerCase(), a);
        saveAccounts();
        startSession(a);
        return a;
    }

    /** Desktop doReset(): a patient proves who they are with the contact number they registered with. */
    static Account resetPassword(String userIn, String contactIn, String pw, String pw2) {
        Account a = ACCOUNTS.get(userIn.trim().toLowerCase());
        if (a == null || !a.role.equals("patient") || a.contact.isEmpty() || !digits(a.contact).equals(digits(contactIn)))
            throw new UserError("We could not verify that username and number.");
        if (pw.length() < 6) throw new UserError("Password must be at least 6 characters.");
        if (!pw.equals(pw2)) throw new UserError("Passwords do not match.");
        Account updated = makeAccount(a.username, a.role, a.name, a.contact, pw);
        ACCOUNTS.put(a.username.toLowerCase(), updated);
        saveAccounts();
        return updated;
    }

    /** Desktop startSession(): a patient's first sign-in also creates their clinic record. */
    static void startSession(Account a) {
        if (a.role.equals("patient") && recordOf(a.name) == null) {
            PATS.add(pat(nextPatId(), a.name, "", "", a.contact, "-"));
            saveData();
        }
    }
The checks and messages are the desktop's. Two additions for the web: login hashes the password even when the username does not exist, so a wrong username takes as long as a wrong password; and register asks for the contact number on file when the name matches a clinic record, so nobody can register as "Juan Dela Cruz" and see his appointments.
Step 3.3: Patient actions
Paste above the last }:
    // =====================================================================
    //  PATIENT ACTIONS  (desktop: book, cancelDialog)
    // =====================================================================

    static Appt book(Account who, String doctorName, String dateText, String timeText) {
        Doctor d = doctor(doctorName);
        if (d == null) throw new UserError("Please choose a doctor.");
        // The desktop lists only allowed these choices; a website must check them because anyone can send anything.
        LocalDate date = toDate(dateText);
        if (!withinNextDays(date)) throw new UserError("Please choose a date from the list.");
        if (date.getDayOfWeek() == DayOfWeek.SUNDAY) throw new UserError("The clinic is closed on Sundays.");
        LocalTime time = toTime(timeText);
        if (time == null || !allSlots().contains(time)) throw new UserError("Please choose a time slot from the list.");
        // The same three checks as the desktop book() method.
        if (date.equals(LocalDate.now()) && !time.isAfter(LocalTime.now())) throw new UserError("That time has already passed today.");
        for (Appt a : APPTS)
            if (a.doc.equals(d.name) && a.date.equals(date) && a.time.equals(time) && !a.status.equals("Cancelled"))
                throw new UserError("That slot is already booked. Pick another time.");
        for (Sched s : SCHEDS)
            if (s.doc.equals(d.name) && s.date.equals(date) && !s.ok) throw new UserError(d.name + " is not available on that date.");
        Appt a = appt(who.name, d.name, date, time.toString(), "Scheduled");
        APPTS.add(a);
        saveData();
        return a;
    }

    /** Patients may cancel their own appointments; clinic staff may cancel any appointment. */
    static Appt cancel(Account who, String id) {
        Appt a = findAppt(id);
        if (a == null || !(isAdmin(who) || a.patient.equals(who.name))) throw new UserError(404, "Appointment not found.");
        if (!live(a)) throw new UserError("This appointment can no longer be cancelled.");
        a.status = "Cancelled";
        saveData();
        return a;
    }
The desktop's drop-down lists only offered valid choices. A web server must check every value itself, because anyone can send any value to /api/book. After those checks come the desktop's own three: the time has not passed, the slot is free, and the doctor is available that day. cancel lets a patient cancel only their own appointments.
Step 3.4: Clinic staff actions
Paste above the last }:
    // =====================================================================
    //  CLINIC STAFF ACTIONS  (desktop: wAppMgmt, wQueueMgmt, patientDialog, wSchedMgmt, scheduleDialog)
    // =====================================================================

    static Appt confirm(String id) {
        Appt a = findAppt(id);
        if (a == null) throw new UserError(404, "Appointment not found.");
        if (!a.status.equals("Scheduled") && !a.status.equals("Upcoming")) throw new UserError("Only scheduled appointments can be confirmed.");
        a.status = "Confirmed";
        saveData();
        return a;
    }

    /** "Call Next Patient": the first waiting patient goes in to see the doctor. */
    static QEntry callNext() {
        for (QEntry q : QUEUE)
            if (q.status.equals("Next") || q.status.equals("Waiting")) {
                q.status = "In Consultation";
                saveData();
                return q;
            }
        throw new UserError("No patients are waiting.");
    }

    static QEntry callPatient(int index, String name) {
        QEntry q = queueEntry(index, name);
        if (q.status.equals("In Consultation") || q.status.equals("Completed")) throw new UserError(q.name + " cannot be called right now.");
        q.status = "In Consultation";
        saveData();
        return q;
    }

    static QEntry completePatient(int index, String name) {
        QEntry q = queueEntry(index, name);
        if (!q.status.equals("In Consultation")) throw new UserError(q.name + " is not in consultation.");
        q.status = "Completed";
        saveData();
        return q;
    }

    /** Queue entries have no ID, so the page sends the row number and the name. Both must still match. */
    private static QEntry queueEntry(int index, String name) {
        if (index < 0 || index >= QUEUE.size() || !QUEUE.get(index).name.equals(name))
            throw new UserError("The queue has changed. Please try again.");
        return QUEUE.get(index);
    }

    /** Add Patient (when id is empty) or Edit Patient, with the same checks as the desktop patient dialog. */
    static Pat savePatient(String id, String nameIn, String ageIn, String gender, String contactIn) {
        String n = clean(nameIn, 60), c = clean(contactIn, 20), a = ageIn.trim();
        if (n.isEmpty()) throw new UserError("Please enter the patient's name.");
        if (!a.matches("\\d{1,3}") || Integer.parseInt(a) > 120) throw new UserError("Please enter a valid age (0-120).");
        if (!c.matches("[0-9+\\-\\s]{7,15}")) throw new UserError("Please enter a valid contact number.");
        if (!GENDERS.contains(gender)) throw new UserError("Please choose a gender.");
        Pat p;
        if (id.isEmpty()) {
            p = pat(nextPatId(), n, a, "", c, "-");
            PATS.add(p);
        } else {
            p = findPat(id);
            if (p == null) throw new UserError(404, "Patient not found.");
        }
        p.name = n;
        p.age = a;
        p.contact = c;
        p.gender = gender;
        saveData();
        return p;
    }

    static Pat deletePatient(String id) {
        Pat p = findPat(id);
        if (p == null) throw new UserError(404, "Patient not found.");
        PATS.remove(p);
        saveData();
        return p;
    }

    static Sched addSchedule(String doctorName, String dateText, String slots) {
        Doctor d = doctor(doctorName);
        if (d == null) throw new UserError("Please choose a doctor.");
        LocalDate date = toDate(dateText);
        if (!withinNextDays(date)) throw new UserError("Please choose a date from the list.");
        if (!SLOT_CHOICES.contains(slots)) throw new UserError("Please choose an available time.");
        Sched s = sched(d.name, date, slots, true);
        SCHEDS.add(s);
        saveData();
        return s;
    }

    static Sched toggleSchedule(int id) {
        Sched s = findSched(id);
        s.ok = !s.ok;
        saveData();
        return s;
    }

    static Sched removeSchedule(int id) {
        Sched s = findSched(id);
        SCHEDS.remove(s);
        saveData();
        return s;
    }
Queue entries have no ID in MediQueueData, so the page sends the row number and the patient's name, and queueEntry refuses the action if the queue changed in the meantime. savePatient adds a patient when id is empty and edits one otherwise.

    //  SCREEN DATA  (desktop: the w...() and stat() methods that fill each page)

    /** Everything the signed-in user's pages need. The web server sends this to the browser as JSON. */
    static Map<String, Object> stateFor(Account who) {
        LocalDate today = LocalDate.now();
        LocalTime now = LocalTime.now();
        Map<String, Object> s = obj(
                "user", obj("name", who.name, "firstName", firstName(who.name), "username", who.username,
                            "role", who.role, "roleLabel", isAdmin(who) ? "Clinic Staff" : "Patient"),
                "now", obj("date", today.toString(), "dateLabel", today.format(DATE_FMT), "time", now.format(CLOCK), "hour", now.getHour()),
                "fee", FEE,
                "doctors", doctorList());
        if (isAdmin(who)) addStaffData(s, today);
        else addPatientData(s, who, today);
        return s;
    }

    private static void addPatientData(Map<String, Object> s, Account who, LocalDate today) {
        List<Appt> mine = appointmentsOf(who.name);
        Appt upcoming = null;
        for (Appt a : mine) if (live(a) && !a.date.isBefore(today)) { upcoming = a; break; }
        Pat record = recordOf(who.name);
        int myNumber = queueNumberOf(who.name);

        List<Object> rows = new ArrayList<>();
        for (int i = 0; i < QUEUE.size(); i++) {
            QEntry q = QUEUE.get(i);
            boolean mineRow = i == myNumber - 1;
            // Web only: other patients appear as "Juan C.", so patients see only their own full name.
            rows.add(obj("no", i + 1, "name", mineRow ? q.name : shortName(q.name), "status", q.status, "mine", mineRow));
        }

        List<Object> doctorChoices = new ArrayList<>(), dates = new ArrayList<>(), times = new ArrayList<>();
        for (Doctor d : DOCTORS) doctorChoices.add(obj("value", d.name, "label", d.name + " - " + d.spec));
        for (int i = 0; i < DAYS_AHEAD; i++) {
            LocalDate d = today.plusDays(i);
            if (d.getDayOfWeek() != DayOfWeek.SUNDAY) dates.add(obj("value", d.toString(), "label", d.format(DAY_FMT)));
        }
        for (LocalTime t : allSlots()) times.add(obj("value", t.toString(), "label", t.format(TIME_FMT)));

        s.put("profile", obj("name", who.name, "patientId", record == null ? "-" : record.id,
                             "contact", record == null || record.contact.isEmpty() ? "-" : record.contact));
        s.put("appointments", appointmentList(mine));
        s.put("upcoming", upcoming == null ? null
                : obj("date", upcoming.date.toString(), "dateLabel", upcoming.date.format(DATE_FMT), "doctor", upcoming.doc));
        s.put("queue", obj("myNumber", myNumber, "rows", rows));
        s.put("booking", obj("doctors", doctorChoices, "dates", dates, "times", times));
    }

    private static void addStaffData(Map<String, Object> s, LocalDate today) {
        int current = 0;
        for (int i = 0; i < QUEUE.size(); i++) if (QUEUE.get(i).status.equals("In Consultation")) current = i + 1;
        int onDuty = 0;
        for (Doctor d : DOCTORS)
            for (Sched x : SCHEDS) if (x.doc.equals(d.name) && x.date.equals(today) && x.ok) { onDuty++; break; }
        int active = 0, cancelled = 0;
        for (Appt a : APPTS) {
            if (live(a)) active++;
            if (a.status.equals("Cancelled")) cancelled++;
        }
        s.put("stats", obj("appointments", APPTS.size(), "patients", PATS.size(), "currentQueue", current,
                           "onDuty", onDuty, "doctorCount", DOCTORS.length));
        s.put("summary", obj("active", active, "inQueue", count("Waiting", "Next"), "completed", count("Completed"), "cancelled", cancelled));
        s.put("counters", obj("waiting", count("Waiting", "Next"), "inConsultation", count("In Consultation"), "completed", count("Completed")));
        s.put("appointments", appointmentList(sortedAppts(APPTS)));

        List<Object> rows = new ArrayList<>();
        for (int i = 0; i < QUEUE.size(); i++) {
            QEntry q = QUEUE.get(i);

/**
 * MediQueue Web - the clinic system as a website.
 *
 * This class starts a small web server that comes with the JDK (no Tomcat, Maven or libraries needed):
 *   - Files in the web/ folder (index.html, app.css, app.js) are sent to the browser. They draw the screens.
 *   - Addresses that start with /api/ run the clinic rules in MediQueueService and answer with JSON.
 *   - MediQueueData saves everything to mediqueue-data.txt and mediqueue-users.txt, as in the desktop app.
 *
 * Run:  java -jar MediQueueWeb.jar           then open http://localhost:8080
 *       java -jar MediQueueWeb.jar 9090      use a different port
 *       java -jar MediQueueWeb.jar --lan     also let phones and other computers on your network open it
 */
public class MediQueueWeb {

    static final String COOKIE = "mq_session";
    static final long SESSION_LENGTH_MS = 12L * 60 * 60 * 1000;   // a sign-in lasts 12 hours
    static final int MAX_BODY_BYTES = 16 * 1024;                   // forms are small; refuse anything bigger

    /** Browser security rules for our pages: only load scripts and styles from this server. */
    static final String CSP = "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; "
            + "connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'";
    static final Map<String, String> TYPES = Map.of(
            "html", "text/html; charset=utf-8", "css", "text/css; charset=utf-8", "js", "text/javascript; charset=utf-8",
            "svg", "image/svg+xml", "png", "image/png", "ico", "image/x-icon");

    /** Who is signed in on a browser. The browser keeps a random token in a cookie; this remembers whose it is. */
    static final class Session {
        final String username;
        final long started = System.currentTimeMillis();
        Session(String username) { this.username = username; }
        boolean expired() { return System.currentTimeMillis() - started > SESSION_LENGTH_MS; }
    }
    static final Map<String, Session> SESSIONS = new ConcurrentHashMap<>();
    static final SecureRandom RANDOM = new SecureRandom();
}
TYPES tells the browser what kind of file it is receiving. CSP (Content Security Policy) tells the browser to run only scripts and styles that come from this server, which blocks injected code. SESSIONS remembers which username each sign-in token belongs to.

    public static void main(String[] args) throws IOException {
        int port = 8080;
        boolean lan = false;
        for (String a : args) {
            if (a.equals("--lan")) lan = true;

        HttpServer server;
        try {
            server = HttpServer.create(address, 0);
        } catch (BindException e) {
            System.err.println("Port " + port + " is already in use (is MediQueue Web already running?).");
            System.err.println("Close the other program, or start on another port:  java -jar MediQueueWeb.jar " + (port + 1));
            System.exit(1);
            return;
        }
        server.createContext("/api/", MediQueueWeb::handleApi);
        server.createContext("/", MediQueueWeb::handleFile);
        server.setExecutor(Executors.newFixedThreadPool(8));
        server.start();

        System.out.println("MediQueue Web is running.");
        System.out.println("  Open in your browser:  http://localhost:" + port);
        if (lan) printNetworkAddresses(port);
        System.out.println("  Web pages from:        " + (Files.isDirectory(Paths.get("web")) ? Paths.get("web").toAbsolutePath() : "the copy inside the .jar file"));
        System.out.println("  Data saved in:         " + Paths.get("").toAbsolutePath());
        System.out.println("  Press Ctrl+C to stop.");

    private static void printNetworkAddresses(int port) {
        try {
            for (NetworkInterface ni : Collections.list(NetworkInterface.getNetworkInterfaces())) {
                if (!ni.isUp() || ni.isLoopback()) continue;

        }

    // =====================================================================
    //  /api/...  (the clinic actions, answered with JSON)
    // =====================================================================
    private static void handleApi(HttpExchange ex) throws IOException {
        try {
            Map<String, String> form = Collections.emptyMap();
            if (ex.getRequestMethod().equals("POST")) {
                // Our own page always sends this header. Other websites cannot add it, so they cannot make a
                // signed-in browser send us requests behind the user's back ("cross-site request forgery").
                if (!"1".equals(ex.getRequestHeaders().getFirst("X-MediQueue"))) throw new UserError(403, "Request blocked.");
                form = readForm(ex);
            }
            String request = ex.getRequestMethod() + " " + ex.getRequestURI().getPath();
            Object answer;
            synchronized (MediQueueData.class) {   // one request at a time touches the data, like one desktop window
                answer = route(ex, request, form);
            }
            sendJson(ex, 200, answer);
        } catch (UserError e) {
            sendJson(ex, e.status, obj("error", e.getMessage()));
        } catch (RuntimeException e) {
            e.printStackTrace();
            if (ex.getResponseCode() == -1) sendJson(ex, 500, obj("error", "Something went wrong on the server."));
        } finally {
            ex.close();
        }
    }

    /** Decides what to do for each address. Every action is a method in MediQueueService. */
    private static Object route(HttpExchange ex, String request, Map<String, String> form) {
        switch (request) {
            // ---------- asked by the page when it opens: who is signed in on this browser? (null = nobody) ----------
            case "GET /api/state": {
                Account me = signedInUser(ex);
                return obj("ok", true, "state", me == null ? null : stateFor(me));
            }

            // ---------- signing in and out (no account needed) ----------
            case "POST /api/login": {
                String role = field(form, "role").equals("admin") ? "admin" : "patient";
                Account a = login(field(form, "username"), field(form, "password"), role);
                startBrowserSession(ex, a);
                return reply(a, "Welcome, " + firstName(a.name) + "!", "green");
            }
            case "POST /api/register": {
                Account a = register(field(form, "name"), field(form, "contact"), field(form, "username"),
                                     field(form, "password"), field(form, "password2"));
                startBrowserSession(ex, a);
                return reply(a, "Welcome, " + firstName(a.name) + "!", "green");
            }
            case "POST /api/reset": {
                Account a = resetPassword(field(form, "username"), field(form, "contact"), field(form, "password"), field(form, "password2"));
                SESSIONS.values().removeIf(s -> s.username.equalsIgnoreCase(a.username));   // sign-ins with the old password end
                return obj("ok", true, "message", "Password updated. You can now sign in.", "tone", "green", "username", a.username);
            }
            case "POST /api/logout":
                endBrowserSession(ex);
                return obj("ok", true, "message", "You have been logged out.", "tone", "green");
            default:
                break;
        }

        Account me = signedInUser(ex);
        if (me == null) throw new UserError(401, "Please sign in first.");

        switch (request) {
            // ---------- patients ----------
            case "POST /api/book": {
                if (isAdmin(me)) throw new UserError(403, "Only patients can book appointments.");
                Appt a = book(me, field(form, "doctor"), field(form, "date"), field(form, "time"));
                return reply(me, "Booked with " + a.doc + " on " + a.date.format(DATE_FMT) + " at " + a.time.format(TIME_FMT), "green");
            }
            case "POST /api/cancel": {   // patients cancel their own appointments; staff can cancel any
                Appt a = cancel(me, field(form, "id"));
                return reply(me, "Appointment " + a.id + " has been cancelled.", "red");
            }

            // ---------- clinic staff ----------
            case "POST /api/confirm":
                staffOnly(me);
                confirm(field(form, "id"));
                return reply(me, "Appointment confirmed.", "green");
            case "POST /api/queue/next":
                staffOnly(me);
                return reply(me, "Now calling " + callNext().name, "green");
            case "POST /api/queue/call":
                staffOnly(me);
                return reply(me, "Now calling " + callPatient(number(form, "index"), field(form, "name")).name, "green");
            case "POST /api/queue/complete":
                staffOnly(me);
                return reply(me, "Consultation completed for " + completePatient(number(form, "index"), field(form, "name")).name + ".", "green");
            case "POST /api/patients/save":
                staffOnly(me);
                savePatient(field(form, "id"), field(form, "name"), field(form, "age"), field(form, "gender"), field(form, "contact"));
                return reply(me, "Patient saved.", "green");
            case "POST /api/patients/delete":
                staffOnly(me);
                deletePatient(field(form, "id"));
                return reply(me, "Patient deleted.", "red");
            case "POST /api/schedules/add":
                staffOnly(me);
                addSchedule(field(form, "doctor"), field(form, "date"), field(form, "slots"));
                return reply(me, "Schedule added.", "green");
            case "POST /api/schedules/toggle": {
                staffOnly(me);
                Sched s = toggleSchedule(number(form, "id"));
                return reply(me, s.ok ? "Schedule marked available." : "Schedule marked not available.", "green");
            }
            case "POST /api/schedules/remove":
                staffOnly(me);
                removeSchedule(number(form, "id"));
                return reply(me, "Schedule removed.", "red");
            default:
                throw new UserError(404, "Not found.");
        }
    }

    /** The usual answer after a change: a message for the pop-up, its colour, and the fresh screen data. */
    private static Map<String, Object> reply(Account me, String message, String tone) {
        return obj("ok", true, "message", message, "tone", tone, "state", stateFor(me));
    }

    private static void staffOnly(Account me) {
        if (!isAdmin(me)) throw new UserError(403, "Only clinic staff can do that.");
    }

    private static String field(Map<String, String> form, String name) {
        String v = form.get(name);
        return v == null ? "" : v;
    }

    private static int number(Map<String, String> form, String name) { return toInt(field(form, name)); }
Every request to /api/... passes through handleApi:
1.A POST must carry the header X-MediQueue: 1. The page always sends it and other websites cannot, which blocks cross-site request forgery.
2.The form fields (name=value&...) are read into a map.
3.synchronized (MediQueueData.class) lets one request at a time touch the data, so two requests never save the same file at the same moment.
4.route picks the action from the method and address, such as POST /api/book, and calls the matching MediQueueService method. Staff-only actions call staffOnly first.
5.The answer goes back as JSON. A UserError becomes {"error": "..."} with its status code.
Step 4.4: Sign-in sessions
Paste above the last }:
    // =====================================================================
    //  SIGN-IN SESSIONS (a random token kept in a cookie)
    // =====================================================================
    private static void startBrowserSession(HttpExchange ex, Account a) {
        String old = cookie(ex, COOKIE);
        if (old != null) SESSIONS.remove(old);           // every sign-in gets a brand-new token
        SESSIONS.values().removeIf(Session::expired);     // tidy up sign-ins that ran out
        byte[] bytes = new byte[24];
        RANDOM.nextBytes(bytes);
        String token = Base64.getUrlEncoder().withoutPadding().encodeToString(bytes);
        SESSIONS.put(token, new Session(a.username));
        ex.getResponseHeaders().add("Set-Cookie", COOKIE + "=" + token + "; Path=/; HttpOnly; SameSite=Strict");
    }

    private static void endBrowserSession(HttpExchange ex) {
        String token = cookie(ex, COOKIE);
        if (token != null) SESSIONS.remove(token);
        ex.getResponseHeaders().add("Set-Cookie", COOKIE + "=; Path=/; Max-Age=0; HttpOnly; SameSite=Strict");
    }

    private static Account signedInUser(HttpExchange ex) {
        String token = cookie(ex, COOKIE);
        Session s = token == null ? null : SESSIONS.get(token);
        if (s == null) return null;
        if (s.expired()) {
            SESSIONS.remove(token);
            return null;
        }
        return ACCOUNTS.get(s.username.toLowerCase());
    }

    private static String cookie(HttpExchange ex, String name) {
        List<String> headers = ex.getRequestHeaders().get("Cookie");
        if (headers == null) return null;
        for (String header : headers)
            for (String part : header.split(";")) {
                String[] kv = part.trim().split("=", 2);
                if (kv.length == 2 && kv[0].equals(name)) return kv[1];
            }
        return null;
    }
At sign-in the server makes a random token, remembers whose it is in SESSIONS, and gives it to the browser in a cookie. HttpOnly stops page scripts from reading the cookie, and SameSite=Strict stops other websites from sending it. Every later request carries the cookie, so signedInUser knows who is asking. Sign-ins live in memory, so restarting the server signs everyone out.

Paste above the last }:
    // =====================================================================
    //  WEB PAGES (index.html, app.css, app.js from the web/ folder)
    // =====================================================================
    private static void handleFile(HttpExchange ex) throws IOException {
        try {
            String method = ex.getRequestMethod();
            if (!method.equals("GET") && !method.equals("HEAD")) {
                sendText(ex, 405, "Method not allowed");
                return;
            }
            String path = ex.getRequestURI().getPath();
            String name = path.equals("/") ? "index.html" : path.substring(1);
            // Only plain file names such as app.js are served, so tricks like ../ cannot reach other files.
            byte[] body = name.matches("[A-Za-z0-9_-]+\\.(html|css|js|svg|png|ico)") ? webFile(name) : null;
            if (body == null) {
                sendText(ex, 404, "Not found");
                return;
            }
            Headers h = ex.getResponseHeaders();
            h.set("Content-Type", TYPES.get(name.substring(name.lastIndexOf('.') + 1)));
            h.set("Cache-Control", "no-cache");
            h.set("X-Content-Type-Options", "nosniff");
            h.set("Referrer-Policy", "no-referrer");
            h.set("X-Frame-Options", "DENY");
            if (name.endsWith(".html")) h.set("Content-Security-Policy", CSP);
            if (method.equals("HEAD") || body.length == 0) {
                ex.sendResponseHeaders(200, -1);
                return;
            }
            ex.sendResponseHeaders(200, body.length);
            try (OutputStream out = ex.getResponseBody()) { out.write(body); }
        } finally {
            ex.close();
        }
    }

    /** A file from the web/ folder next to the program, or the copy packed inside the .jar when that folder is missing. */
    private static byte[] webFile(String name) throws IOException {
        Path onDisk = Paths.get("web", name);
        if (Files.isRegularFile(onDisk)) return Files.readAllBytes(onDisk);
        try (InputStream in = MediQueueWeb.class.getResourceAsStream("/web/" + name)) {
            return in == null ? null : in.readAllBytes();
        }
    }
handleFile serves only plain file names such as app.js. A name with a slash or .. gets Not found, so nobody can read your source code or the saved data through the browser. webFile looks in the web folder first, then in the copy packed inside the .jar (Phase 10), so the jar also works on its own.

    // =====================================================================
    //  READING REQUESTS AND SENDING ANSWERS
    // =====================================================================

    /** Reads a form the page sent (name=value&name=value) into a map. */
    private static Map<String, String> readForm(HttpExchange ex) throws IOException {
        byte[] body;
        try (InputStream in = ex.getRequestBody()) { body = in.readNBytes(MAX_BODY_BYTES + 1); }
        if (body.length > MAX_BODY_BYTES) throw new UserError(413, "That request is too large.");
        Map<String, String> form = new HashMap<>();
        for (String pair : new String(body, StandardCharsets.UTF_8).split("&")) {
            if (pair.isEmpty()) continue;
            String[] kv = pair.split("=", 2);
            try {
                form.put(URLDecoder.decode(kv[0], StandardCharsets.UTF_8), kv.length > 1 ? URLDecoder.decode(kv[1], StandardCharsets.UTF_8) : "");
            } catch (IllegalArgumentException e) {
                throw new UserError("The form could not be read.");
            }
        }
        return form;
    }

    private static void sendJson(HttpExchange ex, int status, Object body) throws IOException {
        byte[] bytes = Json.write(body).getBytes(StandardCharsets.UTF_8);
        Headers h = ex.getResponseHeaders();
        h.set("Content-Type", "application/json; charset=utf-8");
        h.set("Cache-Control", "no-store");
        h.set("X-Content-Type-Options", "nosniff");
        ex.sendResponseHeaders(status, bytes.length);
        try (OutputStream out = ex.getResponseBody()) { out.write(bytes); }
    }

    private static void sendText(HttpExchange ex, int status, String text) throws IOException {
        ex.getResponseHeaders().set("Content-Type", "text/plain; charset=utf-8");
        if (ex.getRequestMethod().equals("HEAD")) {
            ex.sendResponseHeaders(status, -1);
            return;
        }
        byte[] bytes = text.getBytes(StandardCharsets.UTF_8);
        ex.sendResponseHeaders(status, bytes.length);
        try (OutputStream out = ex.getResponseBody()) { out.write(bytes); }
    }
readForm reads at most 16 KB and turns name=value&... into a map. sendJson and sendText send the answer with its status code and content type.

•☐ http://localhost:8080 in the browser shows Not found. That is expected: index.html arrives in Phase 5.
•☐ http://localhost:8080/api/state shows {"ok":true,"state":null}: the API works and nobody is signed in.

  function h(tag, props, ...children) {
    const el = document.createElement(tag);
    for (const [key, value] of Object.entries(props || {})) {
      if (value === null || value === undefined || value === false) continue;
      if (key.startsWith('on')) el.addEventListener(key.slice(2), value);
      else if (key === 'class') el.className = value;
      else el.setAttribute(key, value === true ? '' : String(value));
    }
    for (const child of children.flat(Infinity)) {
      if (child === null || child === undefined || child === false) continue;
      el.append(child instanceof Node ? child : String(child));

    return el;

Step 6.2: The pop-up message and talking to the server
Paste just above the last line, })();:
  // =====================================================================
  //  POP-UP MESSAGE (the desktop ToastPane)
  // =====================================================================
  let toastTimer = 0;
  function toast(message, tone) {
    const red = tone === 'red' ? ' toast-red' : '';
    toastBox.querySelector('.toast-text').textContent = message;
    toastBox.className = 'toast show' + red;
    clearTimeout(toastTimer);
    toastTimer = setTimeout(() => { toastBox.className = 'toast' + red; }, 3000);
  }

  // =====================================================================
  //  TALKING TO THE JAVA SERVER
  // =====================================================================

  /** Without data: GET /api/<path>. With data: POST it as a form. Returns the server's JSON answer. */
  async function api(path, data) {
    const options = { credentials: 'same-origin', headers: { 'X-MediQueue': '1' } };
    if (data !== undefined) {
      options.method = 'POST';
      options.body = new URLSearchParams(data);
    }
    let response;
    try {
      response = await fetch('/api/' + path, options);
    } catch (e) {
      throw Object.assign(new Error('Cannot reach the MediQueue server. Is it still running?'), { status: 0 });
    }
    let reply = {};
    try { reply = await response.json(); } catch (e) { /* the answer was not JSON */ }
    if (!response.ok) {
      throw Object.assign(new Error(reply.error || 'Something went wrong (error ' + response.status + ').'), { status: response.status });
    }
    return reply;
  }

  /**
   * Sends a change to the server, then shows the reply message and redraws the page with the new data.
   * options.go: page to open afterwards; options.done: run after success; options.error: show errors yourself.
   */
  async function send(path, data, button, options) {
    const opts = options || {};
    if (button) button.disabled = true;
    try {
      const reply = await api(path, data);
      if (reply.state) state = reply.state;
      if (opts.done) opts.done(reply);
      if (opts.go && currentPage() !== opts.go) location.hash = opts.go;   // the hashchange event redraws
      else render();
      if (reply.message) toast(reply.message, reply.tone);
      return reply;
    } catch (error) {
      if (error.status === 401) signedOut('Please sign in again to continue.');
      else if (opts.error) opts.error(error.message);
      else toast(error.message, 'red');
      return null;
    } finally {
      if (button) button.disabled = false;
    }
  }
toast shows a message for 3 seconds with a green or red dot, like the desktop's ToastPane. api talks to the server: without data it sends a GET; with data it POSTs a form plus the X-MediQueue header the server asks for. send is what every button uses: it disables the button while waiting, keeps the new state, redraws the page and shows the server's message. If the server answers 401 (the sign-in ended), it returns to the sign-in card.

  // =====================================================================

  /** Shows content in a dialog over the page. Returns an object with close(). */
  function openModal(content, width, label) {
    const box = h('div', { class: 'dialog w' + width, role: 'dialog', 'aria-modal': 'true', 'aria-label': label }, content);
    const overlay = h('div', { class: 'overlay' }, box);
    const previous = document.activeElement;
    const m = {
      close() {
        const i = modals.indexOf(m);
        if (i === -1) return;
        modals.splice(i, 1);
        overlay.remove();
        app.inert = modals.length > 0;
        if (previous && document.contains(previous)) previous.focus();
      },
    };
    overlay.addEventListener('mousedown', (e) => { if (e.target === overlay) m.close(); });
    document.body.append(overlay);
    modals.push(m);
    app.inert = true;   // the page behind the dialog cannot be clicked or tabbed into
    const first = box.querySelector('input:not([readonly]), select, button');
    if (first) first.focus();
    return m;
  }

  function closeAllModals() {
    while (modals.length) modals[modals.length - 1].close();
  }

  document.addEventListener('keydown', (e) => {
    if (e.key === 'Escape' && modals.length) modals[modals.length - 1].close();
  });

  /** A Yes / No question (the desktop ask()). */
  function ask(title, message, onYes) {
    const m = openModal(h('div', { class: 'dialog-body' },
      h('h2', { class: 'ask-title' }, title),
      h('p', { class: 'muted' }, message),
      h('div', { class: 'btn-row' },
        btn('No', 'neutral', () => m.close()),
        btn('Yes', 'danger', () => { m.close(); onYes(); }))), 380, title);
  }
openModal shows a dialog over the page and puts the cursor in it; Escape or a click outside closes it, and the page behind cannot be clicked while it is open. ask is the desktop's Yes/No question. Phases 7 and 8 build their dialogs on these two.

  const PAGES_WITH_FORMS = ['book', 'patients', 'schedules'];

  // Every 15 seconds, fetch the latest data so the queue moves on screen when staff call the next patient.
  setInterval(async () => {
    if (!state || document.hidden || modals.length || PAGES_WITH_FORMS.includes(currentPage())) return;
    const focused = document.activeElement;
    if (focused && /^(INPUT|SELECT|TEXTAREA)$/.test(focused.tagName)) return;
    try {
      const reply = await api('state');
      if (!state || modals.length) return;   // signed out or a dialog opened in the meantime
      if (!reply.state) {                     // the server no longer knows this sign-in (restarted, or 12 hours passed)
        signedOut('Your session has ended. Please sign in again.');
        return;
      }
      const changed = JSON.stringify(reply.state) !== JSON.stringify(state);
      state = reply.state;
      if (changed) render();
    } catch (error) {
      if (error.status === 401) signedOut('Your session has ended. Please sign in again.');
    }
  }, 15000);
A round is skipped when:
•nobody is signed in, or the tab is hidden (a minimized window or a background tab);
•a dialog is open;
•you are on Book, Patients or Schedules, or the cursor is in a box, so nothing you are typing gets wiped.
The new data is compared with the old as text, so the page only redraws when something really changed. If the server sends no data at all, it has forgotten this sign-in (it was restarted, or 12 hours passed), so the page returns to the sign-in card with a message.

## How it works

     Browser                            Java server (MediQueueWeb.jar)                   Saved files
     -------                            ------------------------------                   -----------
     web/index.html                     MediQueueWeb.java      receives each request
     web/app.css     --- request --->     |                    and checks who is signed in
     web/app.js      <---- JSON -----     v
                                        MediQueueService.java  clinic rules: book, cancel,
                                          |                    call next patient, ...
                                          v
                                        MediQueueData.java     lists + saving   ---> mediqueue-data.txt
                                                                                ---> mediqueue-users.txt

1. The browser loads the page (`index.html`, `app.css`, `app.js`) from the server.
2. `app.js` asks the server for `/api/state`: everything the signed-in user's screens need. Then it draws the page.
3. When you click a button, such as **Book Appointment**, `app.js` sends the form to the server, for example to `/api/book`.
4. `MediQueueService` checks the same rules as the desktop app, and `MediQueueData` saves the change to the text files.
5. The server answers with a message (the pop-up at the bottom of the screen) and the updated data, and the page redraws.

## The API (the addresses the page uses)

| Address | Who | What it does |
|---|---|---|
| `GET /api/state` | anyone | The signed-in user's screen data (`null` when nobody is signed in) |
| `POST /api/login`, `/api/register`, `/api/reset`, `/api/logout` | anyone | Sign in, create a patient account, reset a password, sign out |
| `POST /api/book` | patient | Book an appointment (`doctor`, `date`, `time`) |
| `POST /api/cancel` | patient (own) or staff (any) | Cancel an appointment (`id`) |
| `POST /api/confirm` | staff | Confirm a scheduled appointment (`id`) |
| `POST /api/queue/next`, `/api/queue/call`, `/api/queue/complete` | staff | Call the next patient, call a patient, finish a consultation |
| `POST /api/patients/save`, `/api/patients/delete` | staff | Add, edit or delete a patient record |
| `POST /api/schedules/add`, `/api/schedules/toggle`, `/api/schedules/remove` | staff | Manage doctor schedules |

POST requests are sent as forms (`name=value&...`) with the header `X-MediQueue: 1`. Answers are JSON, for example `{"ok":true,"message":"Appointment confirmed.","state":{...}}` or `{"error":"That slot is already booked. Pick another time."}`.

## What is different from the desktop version

Same features, rules and messages. A few things changed because anyone can open a website:

- Every choice (doctor, date, time slot) is checked on the server, not only limited by the drop-down lists.
- In the queue, patients see their own full name and other patients as "Juan C." Staff still see full names.
- Registering with the exact name of an existing clinic record requires the contact number on that record. Without this, anyone could register as "Juan Dela Cruz" and see his appointments.
- The queue screens update by themselves every 15 seconds, so patients see the queue move when staff call the next patient.
- A sign-in lasts 12 hours, or until the server restarts. Resetting a password signs that account out everywhere.

## The desktop version is still included

`java -jar MediQueue.jar` starts the original Swing app. It uses the same data files, so you can switch between the two, but do not run both at the same time: each one keeps its own copy of the data in memory, and the last one to save wins.

## Troubleshooting

- **`'java' is not recognized`**: the JDK is not installed, or not on your PATH.
- **`'jar' is not recognized` while building**: the Oracle installer puts only `java` and `javac` on your PATH. Add the JDK's `bin` folder (for example `C:\Program Files\Java\jdk-26\bin`) to PATH, then open a new terminal.
- **"Port 8080 is already in use"**: another program (or another copy of MediQueue Web) is using it. Close it, or run `java -jar MediQueueWeb.jar 8081`.
- **The build fails on Windows because a file is in use**: stop the server first, then build.
- **The browser shows an old version of a page**: press **Ctrl + F5**.

## Limitations

- The demo accounts above get their passwords reset every time the server starts (see `loadAccounts()` in `MediQueueData.java`).
- No HTTPS. That is fine on your own computer; on a shared network, other people could read the traffic.
- There is no limit on repeated sign-in or password-reset attempts.
- As in the desktop version, nothing adds new patients to the queue; it starts with the four sample patients.
- All data is kept in two text files: fine for a demo, not for a real clinic.

Appendix: API reference and what changed from the desktop version
A. How the page talks to the server
•Every address starts with /api/. The page reads with GET and changes things with POST.
•A POST body is a form (name=value&name2=value2) and must carry the header X-MediQueue: 1, or the server answers 403 "Request blocked." Other websites cannot add that header, so they cannot send requests through your signed-in browser.
•Signing in sets the cookie mq_session (HttpOnly, SameSite=Strict). The browser sends it back with every request, and the server looks the token up to know who you are. Sign-ins last 12 hours and live in memory, so a restart signs everyone out.
•A change answers {"ok":true,"message":"...","tone":"green","state":{...}}: the pop-up text, its colour, and fresh screen data, so the page redraws without a second request. A refusal answers {"error":"..."} with one of these status codes:
Code	Meaning	Example
200	Done	"Appointment confirmed."
400	A clinic rule said no	"That slot is already booked. Pick another time."
401	Not signed in	"Please sign in first."
403	Wrong role, or the X-MediQueue header is missing	"Only clinic staff can do that."
404	No such address or record	"Appointment not found."
413	The form is over 16 KB	"That request is too large."
500	A bug on the server; the terminal shows the details	"Something went wrong on the server."
B. Every address
Address	Who	Form fields	Message on success
GET /api/state	anyone	none	none; state is null when nobody is signed in
POST /api/login	anyone	role (admin or patient), username, password	"Welcome, Mark!" (the first name)
POST /api/register	anyone	name, contact, username, password, password2	"Welcome, ...!"
POST /api/reset	anyone	username, contact, password, password2	"Password updated. You can now sign in."
POST /api/logout	anyone	none	"You have been logged out."
POST /api/book	patient	doctor, date (2026-10-23), time (09:30)	"Booked with ... on ... at ..."
POST /api/cancel	patient (own) or staff (any)	id (such as A-1003)	"Appointment A-1003 has been cancelled."
POST /api/confirm	staff	id	"Appointment confirmed."
POST /api/queue/next	staff	none	"Now calling Carlo Santos"
POST /api/queue/call	staff	index, name	"Now calling ..."
POST /api/queue/complete	staff	index, name	"Consultation completed for Maria Lopez."
POST /api/patients/save	staff	id (empty for a new patient), name, age, gender, contact	"Patient saved."
POST /api/patients/delete	staff	id (such as P-003)	"Patient deleted."
POST /api/schedules/add	staff	doctor, date, slots	"Schedule added."
POST /api/schedules/toggle	staff	id	"Schedule marked available." or "Schedule marked not available."
POST /api/schedules/remove	staff	id	"Schedule removed."
For the queue, index is the row's place in state.queue.rows and name must match it. If someone else changed the queue first, the server answers "The queue has changed. Please try again." instead of calling the wrong patient.
C. What is inside state
Who	Keys
Everyone	user (name, role), now (today's date and the time), fee, doctors
Patients	profile, appointments (their own), upcoming, queue (myNumber, and rows with short names), booking (the doctor, date and time choices)
Clinic staff	stats, summary, counters, appointments (all), queue (rows with full names), patients, schedules, scheduleOptions
stateFor() in MediQueueService.java builds it from the same lists the desktop's w...() methods read.
D. What changed from the desktop version
Part	Desktop (MediQueue.java)	Web
Screens	Swing panels from buildBody() and the w...() methods	app.js builds HTML with h(), and pageBody() picks the page
Clinic rules	Inside the button handlers (doLogin, doRegister, doReset, book, ...)	MediQueueService.java, reached through /api/...
Data and saving	MediQueueData.java and two text files	The same file, unchanged, and the same two text files
Who uses it	One person at one window	Many browsers at once: a cookie tells them apart, and one request at a time touches the data
Pop-up messages	A toast drawn in Swing	The #toast box in index.html, filled by toast()
Screen size	A desktop window	Phone to desktop; below 860px the sidebar becomes a menu
Features, rules and messages are the same. These rules are new, because anyone who can reach a website can try things a desktop window never allowed:
•Every input is checked on the server. A doctor, date or time that is not in the lists is refused, even if someone edits the page.
•Patients see other patients in the queue as "Juan C."; staff still see full names.
•Registering with the exact name of an existing clinic record needs the contact number on that record, so nobody can register as "Juan Dela Cruz" and see his appointments.
•A wrong username takes as long to check as a wrong password, so the timing does not reveal which usernames exist.
•Resetting a password signs that account out on every browser.
•Sign-ins expire after 12 hours. Page scripts cannot read the cookie (HttpOnly), and other sites cannot use it (SameSite=Strict).
•The server sends security headers (Content-Security-Policy, X-Frame-Options), so the pages run only their own scripts and other sites cannot show them inside a frame.
•The page refreshes every 15 seconds, so the queue moves without a reload.
